# 要望: 確定申告向け取引収益ポートフォリオ

ステータス: 未着手。live 取引の約定・残高が datastore に溜まってから着手する。ペーパー損益は対象外（[paper-trade-adapter.md](./paper-trade-adapter.md)）。

## 背景

bitFlyer 上の自動売買で得た収益を、日本の確定申告（所得税）に使える形で整理したい。  
Vision の「高度なポートフォリオ最適化」とは別物である。ここでのポートフォリオは、**課税期間ごとの取得・処分・損益を法令・国税庁の取扱いに沿って集計し、申告入力と保存用資料を出すこと**を指す。

個人が暗号資産を売却または使用して得た利益は、事業所得等に付随する場合を除き、原則として**雑所得（その他）**に該当する（所得税法上の取扱い。詳細は国税庁「暗号資産に関する税務上の取扱いについて（情報）」および確定申告書等作成コーナーの案内）。

申告書への「暗号資産の計算書」の添付は不要だが、作成コーナーへの入力根拠と、税務調査に備えた保存資料として、計算過程と取引履歴は残す必要がある。

## 法令・公的資料に基づく出力の正

本要望が目指す出力は、次の公的枠組みに合わせる。独自の課税解釈はしない。

| 項目 | 根拠・参照 | 本システムでの扱い |
| --- | --- | --- |
| 所得区分 | 原則「雑所得（その他）」 | 画面・CSV のラベルをこれに揃える。事業所得への再分類はしない |
| 所得金額 | 収入金額 − 必要経費（取得価額・手数料等） | 銘柄・年単位で算出できること |
| 取得価額の評価 | 個人の標準は**総平均法**。**移動平均法**は届出が必要な場合がある | 既定は総平均法。移動平均は明示オプション |
| 計算様式 | 国税庁「暗号資産の計算書」（総平均法用 / 移動平均法用） | 同趣旨の項目を埋めた CSV / 帳票を出す |
| 取引所一次資料 | bitFlyer の**年間取引報告書**および取引履歴 | 突合・取り込みの正本候補。内部約定だけを申告の唯一の根拠にしない |
| 申告書への添付 | 計算書の添付は不要（作成コーナー FAQ） | e-Tax 代行や申告書 PDF の自動提出はしない |
| 保存 | 帳簿・証憑の保存期間の考え方に沿う | 年次エクスポートを再生成可能にし、生履歴も残す |

税制改正（例: 申告分離課税化の議論）が入ったら、**対象課税年の公的資料を正**として計算ロジックと帳票を差し替える。旧年分の再計算は、その年のルールを保持する。

## 確定した置き方

| 項目 | 方針 |
| --- | --- |
| 形 | `apps/bitflyer` 内の税務集計・エクスポート（ドメイン境界）。UI は閲覧とダウンロードのみ |
| 入力の正 | live の約定・入出金・手数料と、取引所から得た年間取引報告書 / CSV |
| 禁止 | `paper` / `dry_run` の擬似損益を税務出力に混ぜること |
| 対象取引所 | 初期は bitFlyer のみ（Vision の単一取引所方針） |
| 法的位置づけ | **申告支援資料の生成**。税務相談・申告代行・税額の最終確定は行わない |

```text
datastore（live 約定・残高・手数料）
        │
        ▼
  tax portfolio（年次集計）
        │  ← 任意で bitFlyer 年間取引報告書 / 履歴 CSV を突合
        ▼
  出力（計算書相当 CSV・明細・サマリ）
        │
        ▼
  apps/ui（閲覧・ダウンロード） / ファイル保存
        │
        × e-Tax 送信・税理士 API・他取引所合算は初期対象外
```

## この要望で満たすこと

1. **課税年（暦年）**を指定して、銘柄ごとの取得・処分数量、取得価額、処分対価、手数料、所得金額を集計できる
2. 既定の計算方法は**総平均法**。国税庁「暗号資産の計算書（総平均法）」に対応する項目を埋めたファイルを出力できる
3. 取引明細（日時、銘柄、売買区分、数量、単価、手数料、内部注文 ID / 取引所注文 ID）を、保存用にエクスポートできる
4. 年次サマリ（収入金額・必要経費・所得金額、銘柄内訳）を UI または CSV で確認できる
5. bitFlyer の年間取引報告書（または同等の公式エクスポート）と突合し、差分があれば申告用出力を止めるか警告する
6. `TRADE_MODE` が `paper` / `dry_run` の履歴は税務集計の対象外である
7. 出力物に「税務上の最終判断ではない」「申告・納税は利用者の責任」である旨を明示する

最初に出す資料（優先順）:

1. 暗号資産の計算書（総平均法）相当の CSV（作成コーナー入力用）
2. 取引明細 CSV（保存・税理士共有用）
3. 年次サマリ（銘柄別所得の一覧）

## この要望でやらないこと

- 確定申告書そのものの作成・e-Tax 送信・税額の自動計算（累進税率の当てはめ）
- 給与所得・他の雑所得・控除との合算や、20 万円ルール等の申告要否判定の断定
- 複数取引所・DeFi・海外ウォレットの合算（単一取引所を超えたら別要望）
- 事業所得・法人税・消費税の帳票
- 税理士法上の税務相談の代替、および「この金額で申告すればよい」という保証
- Vision で非目標としている高度なポートフォリオ最適化・機械学習
- ペーパー損益の税務資料化

移動平均法の本格対応、必要経費の細目（通信費等の按分）、損失の扱いの高度な注記は、総平均法の年次出力が動いてから足す。

## 前提（着手前に揃っていること）

- live 約定・手数料・残高スナップショットが datastore に残る
- 取引所側の注文 ID と内部 ID の対応が取れる
- 年間取引報告書または取引履歴 CSV を取り込み、または手動突合できる経路がある

## 完了の見方

- 指定年・総平均法で、計算書相当 CSV と明細 CSV を再現可能な手順で出せる
- 同一入力に対して再計算結果が一致する（Decimal で固定。浮動小数で丸めない）
- paper / dry_run のデータが出力に混入しないことをテストで固定できる
- Architecture または運用文書に、税務出力の位置づけ（支援資料であり申告の代替ではないこと）が書かれている

## 注意（運用）

- 出力は利用者自身の申告準備用である。法令改正・個別事情は国税庁・税理士の案内を優先する
- API キーや口座識別子をエクスポートファイルやログに不用意に出さない
- 帳票の「法律に基づく」とは、公的計算方法と様式に沿うという意味であり、本リポジトリが税務の法的助言を行うという意味ではない
